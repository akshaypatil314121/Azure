AKS – Node Not Ready Count

Purpose: This SOP provides the procedure to investigate and validate AKS node NotReady conditions and determine the required remediation.

1. Identify the Affected Node

  • From the incident short description, copy the node name.
  • Extract the VMSS name from the node name.

Example:

aks-compute-44764838-vmss

2. Locate the AKS Cluster

  • Navigate to the Azure Resource Group associated with the node.
  • Identify the cluster resource group in the format:
MC_<resourcegroup>_<clustername>_<region>

Example:

MC_OPS-SHD-AKS-EU2-P_OPS-SHD-AKS-EU2-P_eastus2

From the above, the cluster name is:

OPS-SHD-AKS-EU2-P

3. Validate Node Pool and Cluster Status

  • Open the AKS cluster in the Azure Portal.
  • Navigate to Node Pools and confirm all instances are healthy.
  • Go to Diagnose and Solve Problems → Node Health to review detailed node status.

4. Verify VMSS Instance Status

  • Open the VMSS corresponding to the affected node.
  • Go to the Instances tab.
  • Verify the instance status is Running.

5. Check Activity Log for Automatic Remediation

  • Open the VMSS resource.
  • Navigate to Activity Log.
  • Review events related to:
  • Node eviction
  • VMSS instance deletion
  • Autoscaling or replacement actions

6. Validate Node Status Using kubectl

  • Log in to the jump server:
OPSEU2TERM001P
  • Check available contexts:
kubectl config get-contexts
  • Switch to the correct cluster context:
kubectl config use-context <ClusterName>

Example:

kubectl config use-context ops-shd-aks-eu2-p
  • Verify node status:
kubectl get nodes

7. Final Validation & Closure

  • If all aks-compute nodes are in Ready state and functioning normally, the issue can be considered resolved.
  • Since the node pool is configured for autoscaling, VMSS instance replacement is expected behavior.
