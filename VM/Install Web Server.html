SOP: Install Web Server (IIS) on Windows Server in Azure VM

1.0 Objective

This SOP explains how to:

  • Install a simple workload on a Windows Server hosted in Azure
  • Configure Internet Information Services (IIS) as a web server
  • Validate web server accessibility using the VM’s public IP address
  • Allow inbound HTTP traffic using Azure Network Security Group (NSG) rules

2.0 Scope

This procedure applies to Windows Server Virtual Machines hosted in Microsoft Azure, where IIS is required to host basic web applications.

3.0 Background

After deploying a Windows Server VM, organizations typically install workloads such as:

  • Web servers
  • Application servers
  • Database servers

In this SOP, IIS is used as a sample workload to demonstrate how applications can be hosted on a Windows Server VM in Azure.

4.0 Install Web Server (IIS) on Windows Server

4.1 Open Server Manager

  1. Log in to the Windows Server VM using RDP.
  2. Open Server Manager:
    • It opens by default after login, or
    • Open it from Start Menu → Server Manager

4.2 Add Web Server Role

  1. On the Server Manager dashboard, click Add Roles and Features.
  2. Click Next on the welcome screen.
  3. Select the target server (your VM) and click Next.
  4. On the Server Roles page, select Web Server (IIS).
  5. When prompted, click Add Features.
  6. Click Next through all remaining pages, keeping default settings.
  7. Click Install to begin the installation.

4.3 Complete Installation

  1. Wait for the IIS installation to complete.
  2. Once finished, click Close.
✅ Internet Information Services (IIS) is now installed on the VM.

5.0 Validate IIS Installation

5.1 Test Web Access Using Public IP

  1. Go to the Azure Portal.
  2. Navigate to Virtual Machines → Select your VM.
  3. Copy the VM’s Public IP Address.
  4. Open a browser on your local machine.
  5. Enter the URL:
http://<Public-IP-Address>
❌ At this stage, the page may not load and may display a connection error.

6.0 Configure Network Security Group (NSG)

6.1 Understand the Issue

  • IIS listens on port 80 (HTTP).
  • By default, Azure blocks inbound traffic on port 80.
  • The VM’s Network Security Group (NSG) must explicitly allow HTTP traffic.

6.2 Add Inbound Port Rule

  1. In the Azure Portal, open the Virtual Machine.
  2. Go to Networking.
  3. Under Inbound port rules, click Add inbound port rule.
  4. Configure the rule:
  • Source: Any
  • Source port ranges: *
  • Destination: Any
  • Destination port ranges: 80
  • Protocol: TCP
  • Action: Allow
  • Service: HTTP
  • Name: Allow_HTTP
  1. Click Add.
⏳ Wait a few seconds for the NSG rule to apply.

7.0 Final Validation

Refresh the browser page:

http://<Public-IP-Address>
✅ The default IIS home page should now load successfully. The web server is accessible from the internet.

8.0 Outcome

  • IIS is successfully installed on the Windows Server.
  • Azure NSG is configured to allow HTTP traffic.
  • A sample workload (web server) is running on the VM.

This demonstrates how workloads can be deployed and accessed in Azure‑hosted infrastructure.
